# HANDOFF — сайт для «Колесо 93»

Файл для любой модели, которая подхватывает работу. Читать первым, целиком, до любых правок.

## Что это за проект

Демо-сайт шиномонтажа «Колесо 93», Краснодар, Российская 788.
Первый клиент. Показываем образец, потом запускаем на его домене `koleco93.ru`.

- Договорено: **12 000 ₽** — витрина с заявками и запуск, **+8 000 ₽** — каталог с корзиной.
- Старый магазин клиента: `https://koleco93.ru/` (OpenCart, 818 позиций, работает).
- Домен, хостинг и OpenCart **не трогать**, пока клиент не согласился.

## Жёсткие правила (нарушение = брак)

1. **Товары только реальные.** Источник: `data/товары.json` (120 позиций, спарсены с их магазина). Ничего не выдумывать: ни названий, ни брендов, ни цен. Никаких «примерных позиций» и `via.placeholder.com`.
2. **Фото товаров у них нет** — в магазине заглушка `placeholder-220x230.png`. Значит на карточке рисуем схему шины (SVG) или размер крупно текстом, но не поддельные фото.
3. **Наличие не показывать.** У всех 120 позиций в их листинге индикатор 0.1 % и статус «Нет на складе (под заказ)» — это не значит, что товара нет. Пишем «наличие уточним в WhatsApp».
4. Деньги и состав работ клиенту не пересматривать без спроса у владельца проекта.
5. Цифры в текстах сайта — только проверяемые (телефон, адрес, часы, цены из `data/товары.json`).

## Стек

- Статика: HTML + CSS + vanilla JS. Без сборки, без npm, без фреймворков.
- Хостинг: GitHub Pages, репо `remtech-krd/koleso93`, ветка `main`.
- Живой образец: `https://remtech-krd.github.io/koleso93/`
- Шрифты: Oswald + Manrope (Google Fonts). Палитра в `style.css`: `--beton --paper --ink --ink-soft --steel --line --red --panel --panel-line`.
- Заказы: корзина в `localStorage`, кнопка собирает текст и открывает `https://wa.me/79181554435?text=...`. Серверов нет и не надо.

## Как проверять

Python + Playwright уже стоят. Открывать локальный файл через `Path(...).as_uri()`, смотреть консоль и `requestfailed`. Кириллица в консоли Windows ломается — писать скрипты в UTF-8 и запускать `chcp 65001`.
